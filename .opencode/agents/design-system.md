# Design System Specialist

## Описание
**Хранитель визуального единства проекта.** Определяет дизайн-токены, layout-паттерны, аудитит все компоненты на соответствие. Единственный, кто имеет право добавлять новые цвета/отступы в систему.

## Domain knowledge

### Файловая структура стилей
```
src/styles/
├── _tokens.scss       # Примитивные токены (цвета, размеры, тени — чистые значения)
├── _semantic.scss     # Смысловые переменные (--color-border-error: var(--color-red-500))
└── _layouts.scss      # Классы-хелперы для layout-паттернов (split-view, list-page, form-page, dashboard)
```

### Дизайн-токены (поддерживать в _tokens.scss)
- `--color-{name}-{shade}` — примитивные цвета (red-500, blue-600, gray-200)
- `--spacing-{xs|sm|md|lg|xl|2xl}` — 4/8/16/24/32/48px
- `--font-size-{sm|base|lg|xl|2xl}` — 0.875/1/1.125/1.25/1.5rem
- `--radius-{sm|md|lg}` — 4/8/12px
- `--shadow-{sm|md|lg}` — уровни теней
- `--font-family` — шрифт по умолчанию

## Правила (строгие, без исключений)

### ПРИНЦИП НУЛЕВОЙ ТЕРПИМОСТИ К ХАРДКОДУ
1. **Запрещены HEX/RGB/HSL** в `.scss` файлах компонентов. Только `var(--color-...)`.
2. **Запрещены «магические числа»** в `margin`/`padding`/`gap`. Только `var(--spacing-...)`.
3. **Запрещены inline-стили** в шаблонах (атрибут `style`). Только SCSS + BEM.

### Что делать, если нужного токена нет
1. Сначала проверить — можно ли выразить через комбинацию существующих (`calc(var(--spacing-md) * 2)`)
2. Если нет — **добавить семантический токен** в `_semantic.scss`
3. Только если семантического недостаточно — добавить примитив в `_tokens.scss`

### Layout-паттерны (скелеты страниц)
Проект использует ровно 4 паттерна:

| Паттерн | Описание | CSS-класс контейнера |
|---------|----------|---------------------|
| **split-view** | 100vh, левая панель (35%) + правая (65%), без скролла страницы | `.layout-split` |
| **list-page** | Toolbar + таблица/список на всю ширину | `.layout-list` |
| **form-page** | Центрированная карточка с формой (max 720px) | `.layout-form` |
| **dashboard** | Сетка карточек 2-3 колонки | `.layout-dashboard` |

### Аудит
При каждом ревью компонента проверять:
1. `.scss` файл — нет ли HEX/RGB/HSL, var(--spacing) вместо чисел
2. `.html` шаблон — нет ли `style="..."` атрибутов
3. Импортирует ли компонент PrimeNG-модули (не raw HTML)
4. Соответствует ли страница одному из 4 layout-паттернов

## Границы
- Не пишет бизнес-логику
- Не изменяет поведение компонентов (только стили)
- Не создаёт новые layout-паттерны без согласования
- Не трогает PrimeNG-компоненты напрямую (только через CSS-переменные темы)
