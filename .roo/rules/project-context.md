# KPPDF 2.0 — Контекст проекта

## Что это?

**KPPDF 2.0** — сложная CRM-система для управления коммерческими предложениями (КП) с генератором PDF-документов.

## Предметная область

- **Сделки (Deals)** — основная бизнес-сущность. Каждая сделка содержит набор товаров/услуг, клиента, скидки, налоги.
- **Товары / Услуги (Products)** — номенклатура, цены, единицы измерения.
- **Клиенты (Clients)** — контрагенты: юрлица и физлица.
- **Пользователи (Users)** — сотрудники, работающие в системе (менеджеры, администраторы).
- **Документы (Documents)** — сгенерированные PDF коммерческих предложений. История версий.
- **Шаблоны (Templates)** — настройки визуального оформления PDF (логотип, цвета, шрифты).

## Технический стек

- **Angular 21+** — Standalone components, Signals, inject().
- **SCSS + BEM** — стилизация.
- **RxJS** — только HTTP и внешние потоки.
- **PDF-генератор** — вероятно, jsPDF или аналогичная библиотека (будет уточнено).

## Ключевые сценарии

1. Создание коммерческого предложения (выбор клиента, добавление товаров, расчёт суммы, скидок, налогов).
2. Предпросмотр КП перед генерацией.
3. Экспорт в PDF с настраиваемым шаблоном.
4. Отправка КП клиенту (email/ссылка).
5. Управление шаблонами PDF.
6. История изменений документов.

## Архитектурные решения (зафиксированные)

- Микро-архитектура: `core/`, `shared/`, `entities/`, `features/`, `pages/`.
- NGRX не используется. Всё состояние — на Signals.
- Строгая типизация, `any` запрещён.
- Компоненты — только Standalone, OnPush, SCSS BEM.
- DI — только через `inject()`.

## Критические замечания

- **Не менять архитектуру без подтверждения.** Любые изменения слоёв, добавление новых библиотек состояния или глобальных паттернов — только после обсуждения.
- **PDF-генерация — ключевая фича.** Вся архитектура должна учитывать потребности генерации документов.
- **Производительность важна** — КП могут содержать 50+ позиций, генерация PDF не должна блокировать UI.
